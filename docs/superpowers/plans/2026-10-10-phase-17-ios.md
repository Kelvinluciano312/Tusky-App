## Context

Tusky ships on Android (Expo SDK 57 + Supabase + Plaid + RevenueCat). The same codebase must now
ship to the Apple App Store as a reliable iPhone **and native iPad** app.

What the app must keep:
- the same screens, button positions, flows and design as Android.

What the app must gain:
- **Sign in with Apple**;
- the security gaps closed;
- every App Store requirement met.

Exploration found the app is already ~90% iOS-ready:
- cross-platform UI;
- one `Platform.OS` branch;
- keychain-backed sessions;
- tablet layouts from 16g.

The real gaps:
- **Config:** app.json has no iOS config and eas.json has no iOS profiles.
- **Plaid OAuth:** banks need a universal-link `redirect_uri` on iOS.
- **RevenueCat:** it is Play-only (the unchecked 14d-2 Task 9 already designs the fix).
- **Apple sign-in breaks three flows:**
  - delete-account requires a password;
  - two-step marks only `password` sessions;
  - Apple requires token revocation on deletion.
- **iOS gesture conflict:** on the review deck, edge swipe-back fights the deck's own swipe.
- **Paywall:** it has no close button.
- **Data protection:** there is no app lock and no app-switcher privacy.
- **App Review:** reviewers need data to see on a production build.

### Task 4.2 — Sign-in action (`src/lib/apple-auth.ts`)
```ts
export async function signInWithApple(): Promise<{ status: 'canceled' } | { status: 'signed_in'; userId: string; name: string | null }> {
  const rawNonce = Crypto.randomUUID();
  const hashedNonce = await Crypto.digestStringAsync(Crypto.CryptoDigestAlgorithm.SHA256, rawNonce);
  let credential;
  try {
    credential = await AppleAuthentication.signInAsync({
      requestedScopes: [AppleAuthentication.AppleAuthenticationScope.FULL_NAME, AppleAuthentication.AppleAuthenticationScope.EMAIL],
      nonce: hashedNonce,               // Apple embeds the HASH in the token
    });
  } catch (err) { if (appleCanceled(err)) return { status: 'canceled' }; throw err; }
  if (!credential.identityToken) throw new Error('Apple did not return a sign-in token. Try again.');
  const { data, error } = await supabase.auth.signInWithIdToken({ provider: 'apple', token: credential.identityToken, nonce: rawNonce }); // Supabase gets the RAW nonce
  if (error || !data.user) throw error ?? new Error('Sign in with Apple failed.');
  return { status: 'signed_in', userId: data.user.id, name: validatePersonName(appleDisplayName(credential.fullName) ?? '') || null };
}
/** Fresh Apple proof for account deletion; null when the person cancels. */
export async function confirmWithApple(): Promise<{ identity_token: string; authorization_code: string } | null>;
export function useAppleSignInAvailable(): boolean; // Platform.OS==='ios' && isAvailableAsync(), checked once in an effect
```
`confirmWithApple` calls `signInAsync({ requestedScopes: [] })`. It returns null on cancel and
throws if either token is missing. Check `validatePersonName`'s signature in `lib/profile.ts`.
Never log the tokens.

`deleteAccount(ops, userId, proof: DeleteProof | null)` runs in this order:

2. Check the proof:

     single-use.
3. Unchanged: herd, Plaid, personal herd, `deleteUser`.
4. Then `if (grant) await ops.revokeApple(grant).catch(warn)`, then forget the RevenueCat purchaser.
