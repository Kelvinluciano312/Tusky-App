## How to run this plan

This plan is written so that **Sonnet subagents can execute the code tasks without discovering anything on their own.** Every fact a task needs is stated in the task. Rules for the controller (the session that dispatches subagents):

1. **Who does what.** Every task is labelled:
   - **[Pedro]**: dashboards, accounts, money, Apple logins with 2FA, holding the iPhone. Never give these to a subagent.
   - **[Agent]**: code in this repo. One fresh Sonnet subagent per task. Paste the **whole task text** and the **Global Constraints** section into its prompt, plus "read `CLAUDE.md` and `apps/mobile/AGENTS.md` first".
   - **[Pedro + Agent]**: on the iPhone. Pedro taps, and the agent reads logs, compares against the expected column, and applies the fix recipe the task gives.
2. **Order.**
   - Parts A and B can start today. B1's D-U-N-S number can take up to two weeks.
   - **Part C needs no Apple account and no iPhone.** Run C1 → C6 one at a time on `pedro-14d-ios`.
   - Part D needs B1–B3 done and the iPhone in hand. Part E needs Part D green. Part F is last.
3. **After each [Agent] task**, the controller (not the subagent) does all of this before the next task:
   - Runs the task's check commands itself.
   - Reads the diff against the task's **Done when** list.
   - Checks the **Traps** list item by item. Sonnet tends to "improve" nearby code. Any change outside the task's **Files** list is a finding, and gets reverted.
   - Runs the Android smoke check (below).
4. **Stop conditions are real.** When a task says **STOP**, the subagent reports what it saw (the exact error text, the command, the file) and changes nothing more. The controller brings it to Pedro, or redesigns the step itself. A subagent never improvises a workaround for a STOP.
5. **Shell.** Commands in this plan are bash. On Pedro's Windows PC, Claude Code's shell is Git Bash, so they run as written. Never translate them to PowerShell.
6. **Android smoke check** (after C1, C3, C4, C5 and C6), on the `Pixel_7` emulator with Metro running:
   - `node scripts/emu.mjs logs` after each step shows no new JS errors.
   - Sign in. Home loads.
   - Open Settings → Plan, then the paywall. The Test Store plans load.
   - Categories → a custom category → Delete. The confirm dialog appears above the sheet.
   - Connect First Platypus (`user_good` / `pass_good`).

## Global Constraints (paste into every subagent prompt)

- **Branch:** `pedro-14d-ios`, cut from up-to-date `master`. Never push to `master`, and never merge.
- **Android stays identical.** Any behaviour change must sit behind `Platform.OS === 'ios'`, or inside a pure function whose tests show Android's case unchanged.
  - **Old Android builds in the field send no `platform` field.** The server must treat a missing or unknown platform as Android.
- **Never edit `apps/mobile/ios/` or `apps/mobile/android/`.** Both are gitignored and regenerated by prebuild. Native config goes in `app.json`. If a task makes a throwaway `ios/` folder to inspect it, the task deletes it again.
- **Never add the `expo-calendar` config plugin.** It adds Android calendar permissions and changes Play's Data safety answers. iOS purpose strings go straight into `ios.infoPlist`.
- `EXPO_PUBLIC_*` reads use `||` fallbacks, never `??`. Unset values arrive as `''`.
- **Never import `Alert` from `react-native`** (ESLint refuses it). Use `dialog.alert` from `@/components/ui/dialog`.
- **App tests** (`apps/mobile/src/lib/*.test.ts`) start with `/// <reference types="node" />`. They import the module under test by relative `./x.ts` path, never `@/`. A module under test may import other modules only as `import type`, or by relative `./x.ts` path.
- **Edge Function tests** use `import { assertEquals } from 'jsr:@std/assert';` and run with `npx -y deno test --allow-env supabase/functions/_shared/`.
- **Check commands before every commit:**
  - inside `apps/mobile`: `npm run typecheck && npx expo lint && npm test`;
  - for server changes, also the Deno command above.

  All must pass. Paste their tail into your report.
- **Production:** never `--project-ref awiwcgrisyzimzxgddxu`, never `secrets set --env-file`, never `db push` to production. Production steps belong to Pedro. Dev deploys are allowed only where a task says so.
- **No secrets** in the repo, the chat or a commit. `appl_…` and `goog_…` RevenueCat keys are public SDK keys, but they still go in `.env` and EAS, never in code.
- **Comments** match the codebase: short, about why, with the phase tag where the surrounding code has one, e.g. `(Phase 14d-2)`.
- **Commit messages:** `feat(app): … (Phase 14d-2)`, `feat(functions): …`, `docs: …`. One commit per task unless the task says otherwise.
- Stay inside the task's **Files** list. If something outside it looks wrong, write it in your report; don't fix it.

## Review Focus (for whoever reviews the PRs)

1. **Old Android builds still connect banks.** A link-token request with no `platform` must still get `android_package_name` (C3 tests).
2. **No double billing across stores.** With a live Play subscription, the iPhone paywall refuses to sell, and the reverse holds too (C1 `otherStore`; D5 checks it live).
3. **The reinstall wipe can never sign out an Android user.** It runs only on iOS. On a first launch it never deletes a session that was written during that same launch (C5 tests).
4. **On iOS, plan changes never pass a Play replacement to StoreKit.** The "changes at renewal" message comes from `productChange`'s `upgrade` flag. It is true on iOS only if App Store Connect ranks the six products as B2 says. If the ranking ever changes, the message lies.
5. **Dialogs over Sheets on iOS** (C4), checked live in D3.
6. **Once iOS ships, `eas update --channel production` reaches iPhones too.** `runtimeVersion` is `appVersion` on both platforms, so every JS update must be checked on both (F1 records this in `release.md`).

/**
 * RevenueCat's public key for this launch (Phase 14d-2): one per store and per
 * backend. Empty means purchases are off, and the paywall says plans are coming soon.
 */
export function pickRevenueCatKey(i: {
  backend: Backend;
  platform: string;
  keys: { android: string; ios: string; prodAndroid: string; prodIos: string };
}): string {
  if (i.platform !== 'ios' && i.platform !== 'android') return '';
  if (i.backend === 'real') return i.platform === 'ios' ? i.keys.prodIos : i.keys.prodAndroid;
  return i.platform === 'ios' ? i.keys.ios : i.keys.android;
}
```

export type Store = 'play' | 'app_store';

/** The store this device buys through (Phase 14d-2). */
export function deviceStore(platform: string): Store | null {
  if (platform === 'ios') return 'app_store';
  if (platform === 'android') return 'play';
  return null;
}

/** Manage subscription is for a live store purchase of my own; Test Store and comp rows have nothing to manage. */
export function canManage(p: PlanDetail, now: Date): boolean {
  return !!ownPaidPlan(p, now) && (p.store === 'play' || p.store === 'app_store');
}

/** Where Manage subscription goes when RevenueCat has no managementURL. */
export function manageFallbackUrl(platform: string): string {
  return platform === 'ios'
    ? 'https://apps.apple.com/account/subscriptions'
    : 'https://play.google.com/store/account/subscriptions?package=com.ouroborosstudios.tusky';
}

/**
 * The store my own live plan was bought in, when it is not this device's
 * (Phase 14d-2). Buying here would start a second subscription in a second
 * store, billed twice, so the paywall refuses and points there instead.
 */
export function otherStore(p: PlanDetail, now: Date, device: Store | null): Store | null {
  if (!device || !ownPaidPlan(p, now)) return null;
  if (p.store !== 'play' && p.store !== 'app_store') return null;
  return p.store === device ? null : p.store;
}
```
